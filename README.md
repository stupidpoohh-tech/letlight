# 보이ㄷㅏ — Let There Be Light

> 알수록 보이ㄷㅏ

모바일 지식 탐험 게임의 **First Playable Prototype**.
제품 전체가 아니라, 게임의 첫 3~5분을 실제로 플레이하며
아트 방향 · 세계 등장 연출 · 질문 탐험 · 정답 후 세계 변화 · 도감의 감각을
검증하기 위한 Vertical Slice 다.

---

## 실행

빌드 도구가 없다. 정적 파일을 그대로 띄우면 된다.
(ES 모듈이라 `file://` 로는 열 수 없고, 서버가 하나 필요하다.)

```bash
npx http-server -p 8080 -c-1 .
# 또는
python3 -m http.server 8080
```

`http://localhost:8080` 에서 연다.
휴대폰에서 보려면 같은 와이파이에서 `http://<PC의 IP>:8080`.

세로 화면 기준으로 만들었다. 데스크톱 브라우저라면
개발자도구의 기기 모드(390 × 844 정도)로 보는 것을 권한다.

### 확인용 단축 경로

| 주소 | 하는 일 |
|---|---|
| `/` | 처음부터 (오프닝 포함) |
| `/#skip` | 오프닝을 건너뛰고 세계에서 시작 |

진행 상황은 저장하지 않는다. 새로고침하면 언제나 처음부터 다시 시작한다.
첫 경험을 반복해서 검증하는 것이 이 프로토타입의 목적이기 때문이다.

## 구현한 플레이 흐름

1. **오프닝** — 완전한 검정 → `빛이 있으라.` → `빛은 입자이면서 파동이다.`
2. **최초의 빛** — 문장을 터치한 자리에 점 하나가 생기고 천천히 퍼진다
3. **세계 reveal** — 검정 → 광원 → 지평선 실루엣 → 지형 → 질감 → 색
   (한 번에 밝아지지 않는다. 빛이 세계를 발견해 간다)
4. **첫 월드** — 하늘 / 언덕 / 강 / 오솔길. 나무도 꽃도 동물도 아직 없다
5. **질문 등장** — 세 개의 질문이 세계 위에 하나씩 희미하게 피어난다
6. **문제 풀이** — `구름은 왜 흰색으로 보일까?` 4지선다 (정답 B)
7. **오답 처리** — 조용한 되짚기. 점수도 하트도 없다. 다시 고를 수 있다
8. **정답 → 설명** — 짧은 정적 뒤 `정답입니다.`, 그리고 두 문단
9. **구름 등장** — 하늘 한 부분이 희미해지고, 흰 형태들이 모여 구름이 된다
10. **지식 확장** — 구름 주변에 후속 질문 세 개가 피어난다
11. **도감** — 하단에서 이동. `빛`과 `구름` 두 항목, 나머지는 `???`

## 구조

```
index.html              무대(stage) 뼈대
styles/
  tokens.css            색 · 서체 · 리듬
  app.css               화면 전체
src/
  main.js               전체 진행과 하단 이동
  core/
    rng.js              시드 난수 + 값잡음 (같은 시드 = 같은 세계)
    anim.js             tween / easing / loop
    sheet.js            시트 열고 닫기
  data/
    knowledge.js        질문 · 개념 · 도감 항목 (이번 콘텐츠 전부)
  art/
    defs.js             공유 SVG 필터 (손그림 흔들림, 인쇄결, 구름 실루엣)
    landscape.js        세계를 절차적으로 그린다
    cloud.js            구름 생성 · 형성 애니메이션 · 표류
    plates.js           도감 도판
  scenes/
    opening.js          오프닝 연출 전체
    world.js            질문 노드 · 보상 · 확장
    quiz.js             문제 / 다음 발견 preview
    codex.js            도감
```

### 그림을 만드는 방식

배경은 이미지 파일이 아니라 **시드 기반으로 생성한 SVG** 다.
능선은 값잡음으로 뽑은 점을 Catmull–Rom 곡선으로 잇고,
`feTurbulence` + `feDisplacementMap` 으로 선을 손그림처럼 흔든다.
겹마다 위는 볕을 받고 아래로 갈수록 그늘지는 그라디언트를 주고,
능선이 낮아지는 자리에 골 그림자를 깔아 덩어리감을 만든다.

구름은 흩어진 원들을 블러 + 알파 문턱값으로 하나의 실루엣에 녹인 뒤
같은 형태를 그늘 · 몸 · 판화결 · 윤곽선 네 번 그려 쌓는다.
이 덕분에 원들의 위치를 움직이는 것만으로
"작은 형태들이 모여 구름이 되는" 연출이 그대로 나온다.

색은 `#000a14` 하나만 회사 키컬러에서 가져왔다 (오프닝의 어둠).
나머지 키컬러는 이 세계의 낮은 채도와 맞지 않아 쓰지 않았다.

## 실제로 확인한 동작

390 × 844 기준으로 오프닝부터 도감까지 끊김 없이 한 번에 진행되는 것을
브라우저에서 직접 돌려 확인했다.

- 오프닝 전체 (검정 → 문장 → 터치 → 빛 → 단계적 reveal → 세계만 남음)
- 질문 하나씩 피어남 / 선택 시 나머지가 흐려짐
- 오답 → 되짚기 → 재선택 → 정답 → 설명 → 세계 복귀
- 구름 형성과 표류, 후속 질문 세 개 등장
- 도감 목록 ↔ 항목 이동, 구름 · 빛 두 페이지
- 후속 질문 터치 시 `다음 발견` preview
- 360×640 / 390×844 / 430×932 / 820×1180 에서 가로 넘침 없음
- CPU 4배 스로틀 상태에서 reveal 구간 중앙값 16.7ms/frame

## 아직 placeholder 인 부분

- **후속 질문 네 개** (`하늘은 왜 파랄까?`, `그림자는 왜 생길까?`,
  `먹구름은 왜 회색일까?`, `구름은 왜 떨어지지 않을까?`,
  `구름 하나는 얼마나 무거울까?`) 는 문제가 없다.
  누르면 `다음 발견` 한 장만 보여 준다.
- **도감의 빈 자리 세 칸** 은 `???` 로만 표시된다.
- **서체** — 본문은 Gowun Batang / Gowun Dodum (Google Fonts).
  Freesentation 은 `--font-ui` 스택 맨 앞에 두었고
  `styles/tokens.css` 아래쪽에 `@font-face` 자리를 주석으로 남겨 두었다.
  폰트 파일을 `fonts/` 에 넣고 주석만 풀면 바뀐다.
- **저장 없음** — 계정 · 서버 · 로컬 저장 전부 없다.
- **질문들 탭** — 첨부한 홈화면 시안에는 세 번째 탭이 있으나,
  이번 범위는 `세계 ↔ 도감` 두 개로 두었다.

## 다음 프로토타입에서 확장할 수 있는 지점

- `src/data/knowledge.js` 에 질문 하나를 `kind: 'playable'` 로 추가하고
  `rewards` 에 도감 id 를 적으면 두 번째 문제가 그대로 돈다.
  보상 그림만 `src/art/` 에 추가하면 된다.
- 지금 보상은 `revealCloud()` 안에 박혀 있다. 보상 종류가 둘 이상이 되는
  시점에 `reward` 를 데이터로 빼는 것이 첫 리팩터링 지점이다.
- 질문 자리는 화면 비율 좌표로 손으로 찍었다. 질문 수가 늘면
  세계 좌표 기준 배치와 겹침 회피가 필요하다.
- 세계는 시드 하나로 결정된다. 시드를 바꾸면 다른 세계가 나온다.
  월드 확장(두 번째 지형)의 출발점으로 쓸 수 있다.
- 지식 그래프를 외부에서 관리하게 되면 `knowledge.js` 를
  같은 모양의 JSON 으로 바꾸는 것만으로 붙는다.
