# 보이ㄷㅏ — Let There Be Light

> 알수록 보이ㄷㅏ

모바일 지식 탐험 게임의 **First Playable Prototype**.

이 프로토타입이 확인하려는 것은 하나다.

> 질문을 푼다 → 지식을 읽는다 → 세계가 실제로 변한다 → 새 질문이 열린다
>
> 이 루프가 재미있는가?

---

## 실행

빌드 도구가 없다. 정적 파일을 그대로 띄우면 된다.
(ES 모듈이라 `file://` 로는 열 수 없고, 서버가 하나 필요하다.)

```bash
npx http-server -p 8080 -c-1 .
# 또는
python3 -m http.server 8080
```

세로 화면 기준이다. 넓은 화면에서는 늘어나지 않고,
가운데에 모바일 폭(420px)의 틀이 서고 그 안에서만 돌아간다.

화면 좌표가 아니라 무대 좌표를 쓴다는 뜻이라, 새 연출을 붙일 때는
`src/core/stage.js` 의 `stageRect()` / `toStage()` 를 쓰고,
높이를 재야 하면 `vh` 대신 `--vh` 를 쓴다.

| 주소 | 하는 일 |
|---|---|
| `/` | 처음부터 (오프닝 포함) |
| `/#skip` | 오프닝을 건너뛰고 세계에서 시작 |
| `/#skip&from=seedWater` | 앞 노드를 풀린 것으로 두고 씨앗 노드부터 |
| `/#skip&from=waterInfiltration` | 물이 어디로 가는지 묻는 노드부터 |
| `/#skip&from=plantGrowth` | 식물 노드부터 |
| `/#skip&from=treeForm` | 어린나무에서 큰 나무로 가는 노드부터 |
| `/#reset` | 지금까지 알아낸 것을 지우고 처음부터 |

`from=` 은 확인용 지름길이다. 앞선 세계 변화(구름 · 비)는 재생하지 않는다.

알아낸 질문은 이 기기에만 아주 작게 남는다
(`localStorage` 의 `boida.progress.v1`, 푼 질문의 id 목록 하나).
다시 열면 구름 · 비 · 강 · 자란 나무가 그대로 있고, 연출은 다시 틀지 않는다.
세계의 나머지 상태는 전부 이 목록에서 되짚어 낸다. 상태를 두 군데에 두지 않는다.

처음부터 다시 보려면 도감 맨 아래의 `진행 ── 초기화` 를 누른다.
되돌릴 수 없는 일이라 한 번 더 묻는다. 지우면 오프닝부터 다시 시작한다.
주소로는 `#reset` 을 붙여 열어도 같다.

소리를 켜고 끈 것은 진행이 아니라 설정이라, 초기화해도 남는다.

## 구현한 플레이 흐름

```
Opening → World Reveal → 구름 → 비 ─┬─ 씨앗 → 첫 잎 → 어린나무 → 큰 나무
                                    └─ 물은 어디로 가는가 → 물이 들고 간 에너지
```

비까지는 한 줄이고, 비에서 두 갈래로 갈라진다.
한 갈래는 땅 위에서 자라는 것을, 다른 갈래는 땅속으로 들어간 물을 따라간다.

1. **오프닝** — 완전한 검정 → `빛이 있으라.` → `빛은 입자이면서 파동이다.`
2. **최초의 빛** — `빛은 입자이면서 파동이다.` 를 누르면
   그 자리에서 점 하나가 생기고 퍼진다. 플레이어의 터치가 최초의 관측이다.
   소리도 이때 열린다
3. **세계 reveal** — 검정 → 광원 → 지평선 실루엣 → 지형 → 질감 → 색
   (한 번에 밝아지지 않는다. 빛이 세계를 발견해 간다)
4. **첫 월드** — 하늘 / 지평선 / 둥근 지형 / 땅. 구름도 비도 식물도 없다
5. **Node 1** — 하늘의 빈 자리에 `구름은 왜 흰색으로 보일까?` 가 떠오른다
6. **들어가는 문제** — 4지선다. 고른 뒤 바로 판정하지 않고 아주 짧게 멈춘다.
   오답은 왜 아닌지 일러 주고 다시 고를 수 있다. 목숨도 점수도 없다.
   배우기 전의 직관을 건드리는 자리다
7. **지식** — 세계 위로 글 한 편이 올라온다.
   글 맨 아래에 **나오는 문제**가 이어진다. 방금 읽은 것을 처음 보는
   상황에 대 보는 자리다. 화면을 옮기지 않고 같은 글 안에서 푼다.
   맞히면 그 아래에 `세계로 돌아가기` 가 생긴다. 그전에는 버튼 자체가 없다.
   나오는 문제가 아직 없는 노드는 글 끝에 바로 `세계로 돌아가기` 만 있다
8. **세계의 변화 ①** — 하늘 한 부분이 옅어지고, 안개 같은 형태가 모여
   흰 구름 하나가 된다. 그리고 아주 천천히 흐르기 시작한다
9. **Node 2** — 구름 아래에 `구름은 물로 이루어져 있는데,
   왜 처음부터 비가 내리지는 않을까?`
10. **세계의 변화 ②** — 구름의 밀도가 조금 높아지고, 안에서 무언가 움직이고,
    첫 물방울 하나 → 드문 몇 방울 → 일정한 비 → 땅이 젖는다
11. **Node 3** — 비가 내리는 들판 위에 `씨앗은 물을 만나면 왜 깨어날까?`
12. **세계의 변화 ③** — 비가 그치고, 젖은 땅에서 새싹이 올라온다
13. **Node 4** — 새싹 곁에 `우리는 먹어야 살 수 있는데,
    식물은 어떻게 흙과 물, 빛만으로 자랄까?`
14. **세계의 변화 ④** — 바깥의 빛이 닿고 어린나무로 자란다
15. **Node 5** — 비가 그치면 씨앗 질문과 함께 `왜 어떤 물은 땅속으로 스며들고
    어떤 물은 흘러갈까?` 도 같이 열린다. 순서는 플레이어가 정한다
15-1. **물이 들고 간 에너지** — 강 곁에 `강에서 증발한 물은 어떻게
    '열'을 들고 하늘까지 이동할까?` 가 떠오른다.
    알아내고 나면 강과 구름 사이에 숨어 있던 흐름이 드러난다
16. **세계의 변화 ⑤** — 물을 받아들인 땅의 색이 더 짙어지고,
    낮은 곳으로 모인 물이 골짜기를 따라 강이 된다.
    지평선 쪽 물빛 → 앞쪽으로 이어지는 형태 → 수면의 반사 순서로,
    2초 남짓 동안 조용히 드러난다
17. **Node 6** — 어린나무 곁에 `씨앗 속에는 큰 나무의 모양이 들어 있을까?`
18. **세계의 변화 ⑥** — 자라고, 갈라지고, 다시 자란다.
    같은 일이 몇 번 반복된 끝에 큰 나무가 된다
19. **순환** — `구름 → 비 → 강` 을 다 알아내면 한 바퀴가 닫힌다.
    종이 한 장이 올라와 `물의 순환` 을 알리고, 확인을 누르면 물러난다
20. **살아 있는 세계** — 그때부터 구름이 아주 느리게 숨 쉬고,
    강 위로 빛 한 줄이 계속 앞으로 흘러 내려온다
21. **끝 상태** — 하늘 / 지형 / 구름 / 짙게 젖은 땅 / 강 / 큰 나무
22. **백과사전** — 알아낸 것이 질문 · 세계 · 원리 · 순환 네 축으로 쌓인다

## 백과사전

흰 바탕, 산세리프, 가는 선과 여백으로 짠 작은 아카이브다.
카드도 그림자도 쓰지 않는다. 포인트는 muted olive 하나뿐이다.

```
홈  ─┬─ 세계 ─── 세계 상세 ─── 글
     └─ 원리 ─── 원리 상세 ─┬─ 글
                            └─ 세계 상세
```

- **홈** — 발견한 세계 · 발견한 원리 인덱스 블록, 최근 발견, 더 알아볼 것
- **세계** — 발견한 현상과 존재 / 아직 더 열릴 세계
- **원리 상세** — 처음 만난 곳 · 보이는 세계 · 함께 이해한 것 ·
  다음에 다시 나타날 곳 을 가는 선과 점으로 잇는다
- **글** — 승인된 본문은 그대로 두고 조판만 바꿨다

`src/data/library.js` 가 nodes.js 의 노드를 세계와 원리로 묶는다.
진행 판정은 그대로 `state.js` 가 한다.

## 소리

음원 파일을 받지 않는다. 전부 `src/core/sound.js` 가 그 자리에서 만든다.
무게가 0 이고 바깥으로 나가는 요청도 없다.

브라우저는 사람이 한 번 건드리기 전까지 소리를 내주지 않는다.
오프닝의 `빛은 입자이면서 파동이다` 를 누르는 순간이 그 자리다.
최초의 관측이 소리도 연다. 오프닝을 건너뛰었으면 첫 손길이 대신 연다.

**상시** — 걸러 낸 분홍 잡음 한 겹씩. 악기 소리는 쓰지 않는다.

| | 언제 | 어떻게 |
|---|---|---|
| 공기 | 늘 | 거의 들리지 않는 바탕 |
| 비 | 비가 일정해질 때 ~ 그칠 때 | |
| 강 | **고리가 닫힌 뒤부터** | 세계가 살아나는 규칙을 소리도 따른다 |

**한 번** — 낮은 배음 몇 개가 붙었다 길게 사라진다.

| | 언제 |
|---|---|
| `spark` | 오프닝의 터치 |
| `right` | 문제를 맞혔을 때 |
| `reveal` | 세계가 바뀌기 시작할 때 |
| `cycle` | 한 바퀴가 닫혔을 때 |

낮은 소리만 쌓으면 스피커가 작은 기기에서 아무것도 들리지 않는다.
몸통은 낮게 두되 귀에 닿는 배음을 한 겹 얹는다.

끄는 스위치는 두 군데다. 세계 오른쪽 위의 작은 표시와, 도감 홈 맨 아래.
한쪽을 만지면 다른 쪽도 따라온다 (`boida.sound`).
문제를 푸는 동안에는 하단바와 함께 물러난다.
다른 데를 보고 있으면 저절로 멈춘다.

**iOS 의 무음 스위치**는 웹 오디오까지 막는다.
`navigator.audioSession.type = 'playback'` 으로 이 소리가 벨소리가 아니라
재생이라고 알려 두었다. iOS 16.4 이상에서 지나간다.
그 아래 버전에서는 여전히 무음 스위치를 따른다.

## 순환

질문 몇 개가 모여 한 바퀴를 이루면 고리가 닫힌다.
고리가 닫히기 전까지 세계는 가만히 있고, 닫히고 나면
그 고리에 속한 것들이 움직이기 시작한다.

`src/data/cycles.js` 에 항목 하나가 전부다.

```js
waterCycle: {
  title: '물의 순환',
  ring: ['구름', '비', '강', '증발'],            // 고리에 적히는 이름
  requiredNodes: ['cloudWhite', 'rainStart', 'waterInfiltration'],
  badge: 'assets/water-cycle.webp',
  animates: ['cloud', 'river'],                  // 닫히면 움직이는 것들
}
```

`ring` 은 보여 주는 고리이고, `requiredNodes` 는 실제로 판정하는 질문이다.
고리는 **증발한 물이 다시 구름이 되기까지**(`waterLatentHeat`) 알아내야 닫힌다.

**증발 질문은 아직 따로 없다.** 고리 그림에는 자리를 남겨 두었고,
그 질문이 생기면 `requiredNodes` 에 한 줄 더하고
`waterLatentHeat` 의 앞자리를 그쪽으로 옮기면 된다.
지금은 강 질문(`waterInfiltration`)이 바로 잇고 있다.

닫혔는지는 `solved` 에서 그때그때 되짚는다. 따로 저장하지 않는다.
알림은 마지막 질문을 알아내는 그 순간에 한 번만 뜨고,
다시 열었을 때는 알림 없이 이미 움직이는 세계로 돌아온다.

움직임은 두 가지다. 자리를 옮기는 것이 아니라 살아 있다는 정도다.

| 요소 | 하는 일 | 주기 |
|---|---|---|
| 구름 | 아주 옅게 부풀었다 가라앉는다 | 38초 |
| 강 | 빛 한 줄이 먼 곳에서 앞으로 내려온다 | 17초 |

강의 흐름은 강 그림 자체를 마스크로 써서 물길 안에서만 지나간다.
새 그림을 쓰지 않는다.

## 그림

세계와 구름은 저장소 루트에 올린 원본 그림을 쓴다.

| 원본 | 쓰는 곳 |
|---|---|
| `home.png` | 세계 배경 |
| `cloud3.png` | 세계에 나타나는 구름, 구름 도판 |
| `cloud4.png` | 비 도판 |
| `cloud1·2·5.png` | 아직 안 씀. 변환만 해 둔다 |

씨앗에서 첫 잎까지는 아직 원본이 없다. 루트에 아래 PNG 를 올리고
`tools/build-assets.py` 를 돌리면 `assets/` 에 같은 이름의 webp 가 생기고
바로 연결된다. 투명 배경 PNG 를 권한다.

| 원본 | 만들어지는 것 | 쓰이는 순간 |
|---|---|---|
| `tree1.png` | `assets/sprout.webp` | 비가 그친 뒤 올라오는 새싹 |
| `tree2.png` | `assets/young-tree.webp` | 빛을 쓰기 시작한 어린나무 |
| `tree3.png` | `assets/mature-tree.webp` | 같은 일이 반복된 끝의 큰 나무 |

파일 이름이 다를 때는 `tools/build-assets.py` 의 `GROWTH` 에서
`{ 만들어질 이름: 올린 원본 }` 으로 이어 주면 된다.
`encyclopedia1~4.png` (도감 시안)는 아직 쓰지 않는다.

### 강

`river1~5.png` 는 서로 겹쳐 쓰는 다섯 겹이 아니라, 같은 자리에 들어갈
다섯 개의 후보다. 그중 하나만 세계에 쓴다.

| 원본 | 만들어지는 것 | 쓰이는 순간 |
|---|---|---|
| `river2.png` | `assets/river.webp` | 낮은 곳으로 모인 물이 이룬 강 |

`river2.png` 를 고른 이유는 다섯 중에서 가는 끝이 해 바로 아래에 놓이고,
수면의 반사가 해와 한 줄로 이어지며, 앞쪽으로 넓어지면서도 앞 언덕 위로
올라타지 않기 때문이다. 나머지 넷은 지우지 않았다. 바꾸려면
`tools/build-assets.py` 의 `RIVER_MAIN` 한 줄만 고치면 된다.

강의 자리와 크기는 무대 폭이 아니라 무대 높이(`--vh`)를 따른다.
세계 그림이 `object-fit: cover` 로 좌우가 잘리기 때문에, 화면에 보이는
지형의 크기가 무대 높이에 비례한다. `styles/app.css` 의 `.river-anchor` ·
`.river-img` 에 세 숫자(가로 위치 · 세로 위치 · 높이)로 들어 있다.

아직 올라오지 않은 그림이 둘 있다.

| 올릴 원본 | 만들어지는 것 | 쓰이는 곳 |
|---|---|---|
| — | `assets/soil-water.webp` | 지표 아래로 스며든 물 |
| `badge-water-cycle.png` | `assets/water-cycle.webp` | 물의 순환 배지 |

없어도 화면은 깨지지 않는다.
젖은 땅 층은 조용히 빠지고 (`src/art/assets.js` 의 `WATER_LAYERS`),
그 노드의 도감 도판(`plate: 'soil'`) 자리도 비어 있다.
배지 자리에는 그동안 고리 도식이 대신 들어간다.
`badge-water-cycle.png` 를 루트에 올리고 `tools/build-assets.py` 를 돌리면
팝업과 도감의 그 자리에 바로 들어간다.

질문은 방금 생긴 것 곁에서 피어난다. 노드의 `near: 'cloud' | 'growth'` 가
그 대상을 가리키고, 실제 위치는 화면에서 그 요소를 찾아 계산한다.

모두 같은 지점에 심긴 것처럼 아래를 기준으로 겹쳐 그려진다.
그림이 아직 없으면 그 단계는 보이지 않고, 흐름과 진행은 그대로 흐른다.

`home.png` 는 시안이라 상태바 · 톱니바퀴 · 하단바가 함께 그려져 있다.
`tools/build-assets.py` 가 위쪽 UI 를 지우고 아래쪽 하단바를 잘라 낸 뒤
`assets/` 에 webp 로 저장한다. 시안의 하단바 자리는 게임의 하단바가 덮는다.

원본을 다시 올린 뒤에는 다시 돌려야 한다.

```bash
pip install Pillow
python3 tools/build-assets.py
```

`assets/` 만 화면에 쓰인다. 루트의 원본 PNG 는 아무 데서도 읽지 않는다.

## 구조

```
index.html              무대(stage) 뼈대
_headers                Cloudflare Pages 캐시 설정

assets/                 그것을 게임용으로 줄인 것 (webp)
fonts/                  쓰는 글자만 남긴 본문 웹폰트
tools/
  build-assets.py       원본 그림 → assets/
  subset-font.py        쓰는 글자만 남긴 폰트 만들기
styles/
  tokens.css            색 · 서체 · 리듬
  app.css               화면 전체
src/
  main.js               전체 진행과 하단 이동
  core/
    rng.js              시드 난수
    anim.js             tween / easing / loop
    state.js            world state — 노드 상태, 구름, 비
    sheet.js            시트 열고 닫기
  data/
    nodes.js            content — 질문 · 문제 · 지식 · 세계의 변화
  art/
    cloud.js            구름 — 형성 · 표류 · 밀도 · 뒤척임
    rain.js             비
    plates.js           백과사전 도판
  scenes/               presentation
    opening.js          오프닝 연출 전체
    world.js            노드 배치와 세계의 변화
    quiz.js             4지선다
    article.js          지식 (세계 위로 올라오는 글)
    codex.js            백과사전
```

`content(nodes.js)` · `world state(state.js)` · `presentation(scenes/)` 세 층만 나눠 두었다.
노드를 하나 더하려면 `nodes.js` 에 항목을 쓰고,
새 세계 변화가 필요하면 `art/` 에 그림 하나와 `world.js` 의 `EFFECTS` 에 한 줄을 더하면 된다.

### 한 노드의 문제 둘

```js
quiz:     { prompt, answer, choices: [{ key, text, hint }] }   // 들어가는 문제
exitQuiz: { prompt, answer, choices: [{ key, text, hint }] }   // 나오는 문제 (없어도 된다)
```

두 문제는 모양이 같다. 다만 서는 자리가 다르다.
들어가는 문제는 제 화면을 쓰고, 나오는 문제는 글 맨 아래에 붙는다.
보기를 고르는 부분(`mountChoices`)만 둘이 함께 쓴다.

`exitQuiz` 를 써 넣으면 그 노드의 글 아래에 한 걸음이 붙고,
없으면 글을 읽고 바로 세계로 돌아간다. UI 를 따로 만들 일은 없다.

`hint` 는 그 보기를 골랐을 때 조용히 나오는 한마디다. 정답에도 쓴다.
정답의 `hint` 는 방금 얻은 모델을 한 번 더 짚어 준다.

한 노드는 나오는 문제까지 지나야 끝난 것으로 본다. 그때 `markSolved` 가
불리고, 도감에 들어가고, 세계가 바뀌고, 다음 질문이 열린다.
중간에 창을 닫으면 그 질문은 아직 풀지 않은 것으로 남는다.

### 속도

모든 연출의 속도는 손잡이 하나로 조절한다.

- `src/core/anim.js` 의 `RATE`
- `styles/tokens.css` 의 `--rate`

두 값은 **같아야 한다**. `RATE` 는 `tween()` 과 `wait()` 의 시간을 곱하고,
`--rate` 는 CSS 의 `transition-duration` 을 `calc()` 로 곱한다.
JS 가 CSS 전환이 끝나기를 기다리는 자리가 있어서, 둘이 어긋나면 타이밍이 틀어진다.

현재 `0.74`. 1 이 원래 속도이고, 작을수록 빠르다.

### 구름이 만들어지는 방식

그림 한 장을 그냥 띄우지 않는다.
같은 그림을 여러 겹 겹쳐 두고 겹마다 다르게 움직인다.

- **형성** — 흩어진 조각 세 개가 흐릿하게 떠 있다가 가운데로 모여들고,
  그동안 본체가 흐림 → 또렷함으로 밀도를 올린다
- **표류** — 다 만들어진 뒤 아주 느리게 흐른다 (초당 2px 남짓)
- **밀도** — 비가 오기 직전, 어둡게 보정한 겹이 아주 약간 올라온다
- **뒤척임** — 밝게 보정한 겹이 1% 안쪽으로 흔들려 안에서 뭔가 움직이는 느낌을 준다

비는 CSS 로만 떨어진다. transform 만 움직이므로 프레임을 잡아먹지 않는다.

## 무게

한 번 무거워졌다가 줄인 기록이다.

| | 절차 생성 SVG 시절 | 지금 (그림) |
|---|---|---|
| 전송량 | 451 KB | **378 KB** |
| 요청 수 | 30 | **21** (외부 요청 0) |
| 스타일시트 | 190 KB | **18 KB** |
| 서체 | 372 KB | **98 KB** |
| 프레임 (CPU 4배 조임) | 33.4 ms | **16.7 ms** |

세 가지가 원인이었다.

**서체.** Google Fonts 의 한글 웹폰트는 유니코드 구간별로 120개 남짓 쪼개져 있어서,
그 목록을 담은 CSS 만 172 KB 였다. 그 CSS 가 렌더링을 막고 있었다.
지금은 게임에 실제로 나오는 글자만 잘라 내 `fonts/` 에 직접 두고, 외부 요청을 없앴다.

```bash
pip install fonttools brotli
python3 tools/subset-font.py    # 글을 고치면 다시 돌린다
```

없는 글자는 기기 서체로 대체되므로, 깜빡해도 화면이 깨지지는 않는다.

**필터.** 지형을 SVG 로 그리던 시절, 겹마다 `feTurbulence` 를 걸어
같은 난류를 스물몇 번 계산하고 있었다.
배경이 그림 한 장이 되면서 이 비용은 통째로 사라졌다.

**그림.** 원본 2.2 MB PNG 를 1180px webp 로 줄여 170 KB 로 만들었다.
휴대폰에서 필요한 해상도(약 1090px)에 맞춘 크기다.

빌드가 없으므로 저장소를 그대로 올리면 된다.

1. Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Pages** →
   **Connect to Git** → `stupidpoohh-tech/letlight` 선택
2. 빌드 설정

   | 항목 | 값 |
   |---|---|
   | Framework preset | `None` |
   | Build command | *(비워 둔다)* |
   | Build output directory | `/` |
   | Production branch | `claude/boidda-first-playable-sf7fuw` |

3. **Save and Deploy**

`https://<프로젝트명>.pages.dev` 가 나온다.
이후 이 브랜치에 푸시할 때마다 자동으로 다시 배포된다.
