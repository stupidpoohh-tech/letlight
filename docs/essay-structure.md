# 에세이 구조 편집표

글 하나하나를 **도입 · 구간 · 심화** 세 층으로 다시 묶은 기록이다.

문장은 한 자도 고치지 않았다. 쓰지 않은 문단도 없다.
원래 `body` 배열에 있던 문단을 번호로 가리켜 자리만 옮겼다.

## 번호가 가리키는 것

표에 나오는 `[숫자]` 는 **이 편집 직전(`3f2a130`)의 `article.body` 배열 첨자**다.
`### `로 시작하던 기존 소제목도 그 배열의 한 칸이었으므로 같은 번호 체계에 들어간다.

되짚어 보려면:

```bash
git show 3f2a130:src/data/nodes.js > /tmp/orig.js
node -e "import('/tmp/orig.js').then(({NODES})=>
  NODES.cloudWhite.article.body.forEach((t,i)=>console.log(i,t)))"
```

## 글 한 편의 모양

```js
article: {
  title, plate,
  lead: ['…', '…'],                       // 도입. 본문 앞에 조금 크게
  body: [
    '### 구간 제목',                       // 소제목
    '문단',                                // 보통 문단
    { more: '접힘 제목', body: ['…'] },     // 접었다 펴는 심화
    { figure: '도식 이름', caption: '…' },  // 설명 도식 (P3-3)
  ],
}
```

설명 도식은 두 글에만 있다. 무엇을 왜 그렸는지는
[`essay-figures.md`](essay-figures.md) 에 따로 적었다.

읽는 쪽과 도감 재열람 쪽이 같은 `renderArticle()` 을 쓴다.
접힘은 `<details>` 이고, 여닫은 상태는 읽던 자리와 함께 기기에 남는다
(`boida.resume.v1` 의 `folds`).

## 지킨 규칙

| 규칙 | 이유 |
|---|---|
| 문장을 고치거나, 쪼개거나, 더하지 않는다 | 승인된 본문이다 |
| 도입은 **기존 첫 문단들 중에서** 고른다 | 새 문장을 쓰지 않기 위해 |
| 새로 나누는 글은 구간 2~4개 | 더 잘게 쪼개면 흐름이 끊긴다 |
| 이미 소제목이 잘 나뉜 글은 그대로 둔다 | 고칠 이유가 없다 |
| 접힘을 닫아도 앞뒤 문장이 이어져야 한다 | 접힘은 선택이지 생략이 아니다 |
| 출구 문제의 근거는 접지 않는다 | 접힌 채로도 문제를 풀 수 있어야 한다 |

# 확인한 것

- 열한 편 모두 **원문 문단이 한 글자도 바뀌지 않았다.** 정렬해 비교했다.
- 잃어버린 문단 0, 두 번 쓴 문단 0.
- 접힘은 모두 닫힌 채로 열린다. 닫힌 상태로 읽어도 앞뒤 문장이 이어진다.
- 출구 문제의 근거는 어느 글에서도 접힘 안에 들어가 있지 않다.
- 뒤에 설명 도식 둘이 더해졌다(`cloudWhite` · `waterInfiltration`).
  본문 문단은 그대로이고, 문단 사이에 한 칸이 늘었을 뿐이다.
